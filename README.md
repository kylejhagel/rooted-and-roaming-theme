# Rooted and Roaming — Kadence Child Theme

A **WordPress/Kadence child theme** with a Sass source tree and opt-in, Tailwind-inspired reusable components. This is **not** the Tailwind CSS framework and does not include any Tailwind Plus proprietary components.

## Architecture

- `style.css`: WordPress child-theme metadata only (`Template: kadence`).
- `functions.php`: enqueues the compiled CSS **after Kadence's regular frontend enqueues** (priority 30).
- `src/scss/base/`: design tokens (CSS custom properties) and restrained global HTML element rules.
- `src/scss/components/`: opt-in, `rr-` prefixed component classes.
- `src/scss/utilities/`: minimal layout utilities.
- `src/scss/main.scss`: Sass module entrypoint using `@use`.
- `assets/css/theme.css`: compiled asset committed for production; no Node runtime required on Hostinger.

## Develop

Install Node.js and run `npm install` then `npm run dev` to watch SCSS changes. Run `npm run build` before each commit/release to update the deployable CSS. Upload the full child theme folder into `wp-content/themes/` and activate **Rooted and Roaming** with **Kadence** installed.

The committed stylesheet is an initial baseline; run the Sass build to produce a minified release asset and commit that output. A lockfile will be generated by `npm install`; commit it for reproducible dependency installs.

## Kadence compatibility

Use Kadence's native header, layout, block editing, and controls. Configure site-wide palette and typography in Kadence to match the tokens below. Use CSS classes in **Advanced → Additional CSS class(es)** for wrappers (e.g. `rr-card`, `rr-hero`) and components. Kadence Advanced Button block markup may need a suitable wrapper or targeted mapping; CSS classes on a block wrapper do not automatically apply to the inner `a` element. Test in the editor and frontend before rolling out.

Do not add Tailwind Preflight or an aggressive CSS reset, which could override Kadence and third-party blocks.

## Starter components

`rr-hero`, `rr-button` (with `--primary` and `--outline`), `rr-card`, `rr-field`, `rr-container`, `rr-stack`, `rr-section`.

These are intentionally original styles informed by common Tailwind utility/component conventions, rather than copied Tailwind Plus code. Markup/layout stays editable in WordPress. Complex interactive components should use accessible native HTML or tested WordPress block functionality—not CSS-only interactivity.

## Release checklist

1. `npm install`, `npm run build`; review generated CSS.
2. Test Kadence + Kadence Blocks on Hostinger staging, including responsive layout and focus states.
3. Back up WordPress, deploy updated child-theme files, purge Breeze/Hostinger caches.
4. Have Sally approve visual/content changes before production deployment.

**Do not commit** credentials, database dumps, customer information, WordPress uploads, or unapproved private client source files.

## Post cards (Kadence Posts block)

Add `rr-postcards` to the **Posts block wrapper** under Advanced > Additional
CSS class(es). Use the block's post-selection controls to choose the posts and
its layout controls to set columns and responsive behavior. This adapter targets
Kadence's `article.loop-entry` markup, not the core Query Loop / Post Template.
Do not apply the class to an entire page or a wrapper containing unrelated loops.

The theme styles category links, linked titles, excerpts, optional author/date,
and the existing Read More link. Disable author/date or featured images in the
block settings when they are unwanted. Screen-reader text and Kadence's SVG arrow
are retained. All overrides are scoped to `rr-postcards`; other archives and the
RRPG plugin remain unchanged. Preview the frontend; editor parity is not provided
by the theme's existing frontend-only stylesheet enqueue.

Cards use the existing theme tokens, card border, radius, and shadow. These are
an approximation of the supplied RRPG design: the original RRPG CSS was not
available for exact comparison, so no plugin stylesheet is imported or modified.
When that source is available, compare values before extracting shared Sass
mixins; avoid coupling separate plugin and theme build pipelines.

Review in Kadence Preview: selected posts, one and multiple columns, 320px mobile,
long titles, absent categories, short/long excerpts, author/date on and off,
featured images on and off, keyboard focus, and 200% zoom. Read More aligns at the
bottom when the parent grid stretches cards to equal row heights. Kadence remains
responsible for image rendering and the grid. Per-block typography, color, or
spacing overrides may need clearing if they take precedence over these styles.
